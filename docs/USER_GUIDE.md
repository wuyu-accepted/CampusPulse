# CampusPulse 用户与运行手册

本文介绍产品使用、部署与测试方法。所有命令默认从仓库根目录执行。

## 1. 运行前准备

### 只浏览已完成案例

- Windows 10/11；
- Python 3.11–3.13、Node.js 22.6 或更高版本，以及 npm；
- 不需要 API Key；
- 首次缺少前端依赖时需要联网安装。

### 运行新的 LLM 场景

除上述要求外，还需要：

- 一个 OpenAI-compatible Provider；
- 自己的 API Key 和可用模型；
- 与本次运行匹配的 preflight 和 authorization；
- 明确的请求和 Token 预算。

配置 API Key 后，在项目的运行参数页核对发送范围和预算，再确认启动；命令行也提供对应的授权运行入口。

新的授权运行会在私有运行目录保存 `private-model-inputs-v1.json`。每个槽位在网络请求前写入模型实际收到的 system 输入、结构化 user 输入、场景、分支、时间步和输入指纹；该文件用于逐轮复核，不进入公开结果或代码提交。已经完成但当时未开启该记录的运行，可从公开账本重建根帖、直接父消息和引用消息等确定上下文，重建结果会明确标注其证据范围。

## 2. 启动方式

### 完整产品

```powershell
.\START_FULL_SYSTEM.cmd
```

访问 `http://127.0.0.1:4173/campus-pulse`。它同时提供真实工作台 API 和三个已完成案例。

### 开发模式

```powershell
# 终端一
$env:PYTHONPATH="$PWD;$PWD\src"
python -m uvicorn backend.campus_pulse_app:app --host 127.0.0.1 --port 8000

# 终端二
cd src/frontend
npm install
npm run dev
```

## 3. 主要页面

| 页面 | 做什么 |
|---|---|
| 首页 `/campus-pulse` | 看产品价值、三个案例和完整使用流程 |
| 虚拟论坛 `/campus-pulse/forum` | 按时间步看热榜、最新帖、回复、互动、Claim 和治理对象 |
| 结果中心 `/campus-pulse/results` | 查看三种子五方案主验证，并下钻 Natural/A/D 等逐帖机制链 |
| 项目工作台 `/campus-pulse/workbench` | 创建项目、绑定证据、定义场景/政策、计划、运行和下载结果 |
| 系统与证据 `/campus-pulse/system` | 看服务就绪、证据目录、本机模型配置和架构边界 |

## 4. 配置自己的模型 API

1. 启动完整产品。
2. 打开“系统与证据”。
3. 切到“模型配置”。
4. 填写 API Base URL，例如 `https://provider.example/v1`。
5. 填写 Provider 实际支持的模型名称。
6. 填写 API Key。
7. 设置推理强度、温度、最大输出 Token、超时和并发。
8. 点击“保存本机配置”。
9. 可选：点击“发送最小连接测试”。

连接测试只发送固定文本 `Return exactly: {"status":"ok"}`，不发送项目、Profile、Prompt、论坛消息或结果。它没有自动重试，Provider 返回正文也不会被系统保留。

案例中的公开合成帖子可按条查看英文译文。CASE 02 的治理发布与居民直接承接链带有随包交付的审阅译文，离线也可使用；其它公开合成文本的按需翻译复用这里保存的 Base URL、模型和 API Key。翻译请求不写入项目数据库，也不会把密钥返回前端。

### 配置保存在哪里

| 文件 | 内容 | 是否进 Git |
|---|---|---|
| `~/.campus-pulse/provider-config.json` | base URL、模型和非敏感参数 | 否，位于仓库外 |
| `~/.campus-pulse/provider-key` | API Key | 否，位于仓库外 |

API 只返回 `api_key_present=true/false`，不会返回密钥或尾号。前端不使用 localStorage/sessionStorage 保存密钥。配置路由只接受本机 loopback 请求。

### 已冻结运行与页面配置的关系

页面配置用于新运行和本机操作默认值。Hero 运行的 preflight 绑定 endpoint、模型、Prompt renderer 和预算；配置发生变化时需要生成匹配的新 preflight 与 authorization。

## 5. 创建新项目

1. 打开项目工作台，点击“新建项目”。
2. 在“项目信息”选择项目类型，填写项目名称、治理领域与推演目标。
3. 在“事件与方案”填写事件描述、已知信息、待解答问题和涉及群体。世纪馆回放模板使用与保存记录一致的固定条件。
4. 在“确认创建”核对内容，点击“创建项目”统一进入项目总览。世纪馆从总览点击“开启推演”；自定义项目继续检查运行配置。事件已保存，无需重复填写。
5. 自定义运行继续检查“事件设置 → 治理方案 → 运行参数 → 运行监控”。场景表单自动选择已绑定的数据分析；字段缺失会明确提示并定位。

项目用于组织目标、人口与运行记录；事件设置保存具体发生条件；治理方案定义可执行动作；运行参数确定模型、分支和预算。

### 固定 Agent 世界与项目 Profile

每个新项目都使用同一套 1,000-Agent 长期人口。创建项目不会复制一套临时人物；事件只为这些 Agent 叠加本次利益位置、可见信息和运行状态。工作台的“Agent 世界”会物化全部 1,000 个节点，点击任意节点可读取 Profile、Persona、Prompt 蓝图、记忆、关系摘要和当前事件经历。

项目负责人可以在档案抽屉中修改可编辑资料。保存时后端生成一个不可变的项目 Profile 快照；下一次运行通过 SHA-256 绑定该快照，因此修改前后的实验不会混在一起。

### 证据

先在“系统与证据 → 证据目录”登记可用 release，再在项目中绑定。证据快照只给出来源哈希、规模和已审派生资产；原始正文不会通过工作台返回。

### 事件设置

场景至少说明：

- 发生了什么；
- 已知事实与未知说法；
- 谁受到影响；
- baseline、burst、spread、decay 四阶段如何对应时间步；
- 模型禁止补造的现实事实。

### 治理方案

Natural 一般作为无新增治理的基线。其他方案应写成可执行对象，而不是“加强沟通”这类口号，例如：

- 证据卡：列明已知、未知、责任方和更新时间；
- 服务工单：受理对象、SLA、状态与回执；
- 跨群触达：向未被覆盖群体征集复现条件或问题。

## 6. 运行计划、时间步和槽位

`Tick 3` 表示模拟世界的第 3 个时间步。`Tick 3–10` 包含 Tick 3、4、5、6、7、8、9、10。`Tick` 不是实验编号；项目、运行和时间步的含义也在根目录 README 中说明。

“槽位”是一次计划好的 LLM 任务：某个时间步的某个居民或治理角色需要生成一份结构化 turn。一次槽位可能只发一个 HTTP 请求，也可能因合法格式修复发第二个请求；所以请求上限通常大于槽位数。

运行前查看：

- 人口与分支；
- 每 tick 居民上限；
- 治理 LLM 次数；
- endpoint、模型和 reasoning；
- 主槽位、请求与 Token 硬上限；
- 发送字段与隐私扫描；
- checkpoint 和 unknown 处理方式。

ForumTwin v2 的运行模式有三档：

| 界面选项 | 何时调用 LLM | 适用目的 |
|---|---|---|
| 预算化多方案 | 每 Tick 由 Anchor、互动队列和 PPS 激活 16–64 名居民 | 比赛默认；多方案比较与成本控制 |
| 全量关键帧 | 指定 Tick 调用全部 1,000 名 Agent，其余 Tick 预算化 | 企业能力；当前交付只做离线机制验证 |
| 全量逐时间步 | 每 Tick 调用全部 1,000 名 Agent | 企业高预算能力；当前交付不进行付费调用 |

选择全量关键帧时必须填写 0–23 范围内、不重复的 Tick。工作台从服务端 v9 主计划显示准确槽位、请求和 Token 上限；v10 可见性侧车同时冻结项目 Profile 版本、关系注意、好友私聊、动态小群、服务工单与小喇叭匿名规则。不要仅凭“1,000 Agent × Tick 数”估算，因为共享 baseline 和治理主体也属于工作合同。

v2 的一次居民 turn 可同时包含 1 条公开消息、最多 6 个点赞/转发/举报和最多 2 个私聊动作。公开消息使用 v4 合同：Agent 在同一个小喇叭版面内选择实名或匿名发帖/评论；涉及严重、敏感、脆弱处境或担心熟人凭细节认出时，可以匿名，但仍遵守相同的证据标注、Claim、热榜和安全规则。匿名不会创建第二个“树洞”频道。

好友私聊和动态小群属于私有模拟状态。治理主体只能看到隐私保护后的回流和触达指标，不能读取私聊原文或关系边；运行台只显示活动脉冲、群体级传播和经过人工审阅的匿名摘录。

### 交互通道开关

在“运行计划 → 社会可见性合同”中可配置：

- 关系注意：关系影响打开、通知和后续承接，不改变全局热榜排序；
- 好友私聊：允许一对一转述、追问和纠错；
- 动态小群：允许闭集邀请、接受、拒绝、退出和群聊；关闭好友私聊时会自动关闭；
- 服务工单：让求助、受理、SLA 和回执成为可追踪对象；
- 小喇叭可选匿名：允许普通帖子和评论隐藏公开作者栏。

这些开关随运行计划冻结。运行开始后不能为了得到更好曲线而改动。

### 从工作台启动真实 LLM 运行

进入“项目工作台 → 项目总览 → 一键真实 LLM 推演”，按以下顺序操作：

1. 点击卡片右上角“模型与 API”，在本机保存 base URL、模型名、密钥、超时和并发；密钥不会返回浏览器；
2. 选择情景；
3. 选择“快速闭环”或“公域—私域主实验”。后者当前绑定住宿床位分配争议和已经审计的 `yunwu.ai + gpt-5.6-luna` 合同；
4. 点击“生成 Preflight”。这一步只生成运行合同，不发送 Prompt；
5. 核对模型、endpoint、槽位、请求/Token 上限、发送字段、排除字段、隐私扫描和 SHA-256；
6. 勾选一次性确认并启动；
7. 在同一面板查看已提交 checkpoint 数，或进入实时运行台查看逐 Tick 的公开论坛、关系激活、私聊活动、匿名表达、风险信号和治理动作；
8. 浏览器关闭或后端重启后，重新进入项目总览即可按 session 恢复。已结算槽位不会重新调用。

“快速闭环”共 118 个主槽位和 7 个公开 checkpoint，适合确认配置及现场试跑。“公域—私域主实验”共 358 个主槽位和 15 个公开 checkpoint，完整运行 Tick 3–10。版本化 Python 脚本是控制面的内部执行器；一般用户不需要手工选择脚本版本、拼接参数或管理输出目录。

## 7. 监控、暂停和恢复

工作台运行页显示状态、进度、事件和错误。命令行 Hero 还可以查看账本：

```powershell
python scripts\inspect_forum_hero_live_ledger.py `
  --summary-only `
  D:\path\to\authorized-live-ledger.sqlite3
```

恢复规则：

- 已提交槽位不重新调用；
- 已提交消息、记忆、posterior 和治理动作不重复积分；
- DNS/TCP/TLS 建连前可做有限安全重试；
- 请求可能已发送但结果未知时暂停，不能盲目再发；
- 用同一 preflight/authorization/人口/目录继续。

已明确结算为格式或合同失败的请求可以进入受控修复：修复请求沿用同一槽位、同一脱敏输入范围和哈希绑定的修复合同，并受每槽位次数上限约束。Provider 返回明确的 HTTP 错误且确认没有响应正文时，工作台会写入只含 attempt 指纹的替代证据，并允许一次受硬预算约束的补发。只有当请求结果不确定时才暂停；页面会显示 body-free attempt ID。操作员勾选“永久弃用迟到结果”后，后端写入绑定原 attempt 的裁决证据并用同一 Prompt 补发一次；原请求的迟到结果永久不进入模拟状态，替代请求再次 unknown 时不会再显示第二次补发入口。

最新住宿主实验是 366 槽 Resident turn v5 Natural/D 正式运行，结果、四维评估和人话报告统一位于 `evidence/four-dimension-v5-formal-v1/`。条件私聊和动态小群的安全聚合结果已作为前端 sealed asset 保存在 `src/frontend/public/campus-pulse-data/private-channel-summary-public-v1.json`，不再在 `evidence/` 重复保存历史运行目录。

资源分配主验证使用外层恢复器执行这一流程。当前比赛结果在三个完整配对种子后按成本边界停止；下面的命令只用于确有新授权和新实验目标时继续同一账本，不是浏览结果所必需：

```powershell
python scripts\resume_forum_resource_flagship.py `
  --preflight <resource-flagship-preflight-v1.json> `
  --authorization <resource-flagship-authorization-v1.json> `
  --output-dir <authorized-live-output> `
  --api-key-file <local-key-file> `
  --statement-sha256 <authorization-statement-sha256> `
  --stage full
```

恢复器每次只处理有限数量的失败，随后从最近的完整 checkpoint 继续。重复执行同一命令会复用已结算槽位和缓存，不会从头重跑；若连续达到冻结上限仍无法结算，则保存 ledger 与 checkpoint 后停止。

## 8. 查看与解释结果

### 论坛页

按 tick 播放，先看：

1. 热榜和最新帖是否变化；
2. 哪些 Agent 在直接回复、引用、质疑或求助；
3. 治理消息是否进入后续讨论；
4. Claim 是否被支持、挑战、纠正或过期；
5. 点赞、评论、转发和举报可以同时发生，不是互斥动作。

### 结果中心

不要只比较两条总量曲线。优先看：

- Natural↔D、A↔B↔C 两个同预算比较组，不跨激活密度解释消息量；
- 三种子均值与配对区间是否支持稳定方向；
- 分支从哪个共同时间步开始分叉；
- 解释卡是否有直接居民承接；
- 求助是否产生服务回执；
- 回执后是否由同一居民继续反馈；
- 治理是否带来新的追问或信任反作用；
- 失败、noop 和没有自然出现的机制也要保留。

## 9. 世纪馆现场演示项目

场景：学生路过世纪馆，看到羽毛球/乒乓球场地空着，但小程序热门时段连续显示不可预约。系统不预设“关系占位”为真，让正常保护时段、取消未释放、预约未到、重复占位、维护/换场间隙等解释竞争。

### 从前端创建并播放

从“项目工作台 → 新建项目”选择“世纪馆预约争议”。模板自动填写项目与事件，依次检查“项目信息 → 事件与方案 → 确认创建”，点击“创建项目”进入总览，再点击“开启推演”。热榜条目可展开原帖、评论及互动数；展开时自动暂停播放。

建议项目名称为“世纪馆预约服务治理预演”，推演目标为“比较预约信息公开、异常释放工单和跨群触达如何回应空场却不可预约的疑问”。事件条件与保存的运行保持一致。需要更改事件时使用自定义项目。

创建后项目保存在本机数据库，每个项目关联自己填写的一个事件情景。再次演示通过“继续推演”恢复时间步与分支；初始化中断时重试会继续同一项目。演示工作区使用 `_run/demo-workspace/` 下的独立数据库，正常启动保留日常项目。

### 世界页面操作

1. 从 Tick 0 开始播放人口装载、论坛准备与共享初始状态。
2. 在 Tick 3 或 Tick 4 暂停，查看热榜、最新帖、直接回复和独立互动。
3. 在 Tick 5 之后切换 Natural / D，检查同一时间步的治理对象与讨论。
4. 在“校园小世界正在发生什么”中切换“公开论坛 / 好友私聊 / 全部”。网络包含 16 个角色簇与 112 个匿名微角色投影节点，激活随时间步改变；点击节点查看人物资料，点击连线查看对应传播与对话。
5. 播放到 Tick 10 后返回项目工作台，保留项目用于再次演示。

`century-gym-demo` 保存 17 个公开快照：Tick 0–4 为共享基线，Tick 5–10 各有 Natural 与主动治理 D。Tick 0–2 是零公开消息、零 Provider 的初始化快照；Tick 3–10 来自已经完成的 230/230 槽位真实 LLM 运行。现场播放不发送 Provider 请求，也不占用运行授权。

界面播放规则不是前端临时写死的数据。`evidence/century-gym-demo-v2/public-progress/latest.json` 的 `display_contract` 固定了 11 个界面 Tick、Tick 5 分叉、Natural/D 分支、默认 D 分支、播放间隔和播放期间 Provider 调用为 0；manifest 和所有快照都进行 SHA-256 校验。

关系网中的公开曝光边和发光节点由同一 Tick 的原始公开快照计算。少量私聊活动和 12 条可点击摘录来自 `evidence/century-gym-demo-v2/social-world-v1.json`，其 provenance 固定为 `reviewed_synthetic_mechanism_overlay`。选择私聊连线会同时显示往返双方、口语化内容、前后群体角色以及“这段私聊改变了什么”；推荐依次查看 Natural Tick 6/10 和 D Tick 6/8/10。该文件只含宏观角色对、聚合计数和人工批准的匿名合成摘录，不含 Agent 级关系、conversation ID 或原始私聊；它用于展示已实现的私聊机制，不改变世纪馆原始 LLM 运行结论。

录制视频时建议选择“讲解 · 8 秒/步”，在 Tick 3、5、10 自动停留，解释首批帖子、治理对象和分支变化。世纪馆段落可控制在 2 分 30 秒左右。

运行台只展示模拟过程：帖子、直接回复、互动、热榜、聚合关系传播、经审阅的私聊机制摘录、治理对象和 LLM 用量，不展示一整套结果分析，也不链接到住宿案例。完整结果分析只在案例中心的住宿与讲座两个成果案例中呈现。“现场演示”指演示者从新建项目入口手动启动实际运行记录；“在线执行”才表示当场向 Provider 发送新请求，两者不能混用。

### 命令行方式

完整系统统一通过 `.\START_FULL_SYSTEM.cmd` 启动。模型密钥由前端“模型配置”保存到本机用户配置目录，不写入仓库。

## 11. 常见问题

### 页面显示后端未连接

确认 `http://127.0.0.1:8000/campus-pulse/v1/health` 可访问，并确认使用 `backend.campus_pulse_app:app` 启动。

### 保存配置后看不到 API Key

这是正确行为。密钥只可覆盖或删除，不可从系统读取。

### 配置了模型，为什么点击“运行”仍不发请求

完整产品默认关闭 live LLM；正式运行还需要匹配的 preflight、authorization 和执行器。这个限制防止在浏览页面或误点击时产生费用。

### Provider 超时后能否直接重试

仅在确认请求没有离开本机（DNS/TCP/TLS 建连前失败）时才允许有限重试。若可能已发送，先查 Provider 记录与 ledger，不能盲重试。

### 为什么某个治理方案结果不更好

系统没有硬编码赢家。治理可能打开服务入口，也可能暴露稀缺、积压和未完成处理；这正是预演要发现的机制。
